# 深度相机与电脑通信配置

本文说明在 Windows 主机和 WSL2 Ubuntu 中使用 Intel RealSense 深度相机的方法。RealSense 通过 USB 连接，不需要配置 IP 地址或网络路由；需使用 `usbipd-win` 将 USB 设备透传给 WSL2。

## 1. Windows 侧安装与识别

确认 Windows 已启用 WSL2，并安装 `usbipd-win`。可在管理员 PowerShell 中通过 winget 安装：

```powershell
winget install --interactive --exact dorssel.usbipd-win
```

如果上面的包标识不被当前 winget 源识别，请按[微软 WSL USB 设备连接文档](https://learn.microsoft.com/windows/wsl/connect-usb)中的最新方法安装 `usbipd-win`。

将相机连接到电脑的 USB 3 接口，使用支持数据传输的线缆，然后在 Windows 设备管理器中确认设备出现。打开**管理员 PowerShell**，列出 USB 设备并记下 RealSense 对应的 `BUSID`：

```powershell
usbipd list
```

如果列表中没有相机，先更换 USB 3 接口或线缆，并确认 Windows 本身能识别设备。

## 2. 将相机附加到 WSL2

先打开 Ubuntu/WSL 终端并保持运行，以确保 WSL2 虚拟机处于活动状态。仍在管理员 PowerShell 中，将 `<BUSID>` 替换成上一步查到的设备编号：

```powershell
usbipd bind --busid <BUSID>
```

`bind` 通常只需对该设备执行一次。随后在**普通 PowerShell**中附加设备：

```powershell
usbipd attach --wsl --busid <BUSID>
```

附加期间，相机由 WSL2 使用，Windows 端不能同时访问。设备拔插、WSL 重启或 Windows 重启后，通常需要再次执行 `attach`。微软说明和命令细节见[连接 USB 设备到 WSL](https://learn.microsoft.com/windows/wsl/connect-usb)。

## 3. 在 Ubuntu 中验证并启动 ROS 2

在 WSL Ubuntu 中确认 USB 和 RealSense SDK 都能发现相机：

```bash
lsusb
rs-enumerate-devices
```

`lsusb` 应列出 RealSense 设备。若 `rs-enumerate-devices` 命令不存在，可安装 SDK 工具包（包源需已配置）：

```bash
sudo apt update
sudo apt install librealsense2-utils
```

加载 ROS 2 Humble 环境并启动相机节点：

```bash
source /opt/ros/humble/setup.bash
ros2 launch realsense2_camera rs_launch.py
```

如果当前终端还需要本项目的 ROS 包，再加载项目工作区：

```bash
source <项目工作区>/install/setup.bash
```

启动后可在另一终端检查话题：

```bash
ros2 topic list
```

本机 D405 在 WSL2 中实测可用的低负载模式为仅深度流 424×240、5 FPS。启动并检查实际话题帧率：

```bash
ros2 launch realsense2_camera rs_launch.py \
  enable_color:=false \
  depth_module.depth_profile:=424x240x5
```

在另一终端运行：

```bash
ros2 topic hz /camera/camera/depth/image_rect_raw
```

本次实测平均约 5.1 Hz。更高的 640×480、15 FPS 仅深度模式仍出现 `USB SCP overflow` 和帧超时；因此 424×240、5 FPS 是当前 WSL2 透传下经验证的模式，不代表其他主机或相机型号也需使用该设置。

在 D405 上还验证了 RGB 与深度流的关系：关闭深度流时，RGB 画面明显变暗并偏色；同时开启低帧率深度流后，RGB 画面恢复正常。当前 WSL2 下可用以下配置降低总带宽，同时保持两种流开启：

```bash
ros2 launch realsense2_camera rs_launch.py \
  enable_depth:=true \
  depth_module.color_profile:=424x240x5 \
  depth_module.depth_profile:=424x240x5
```

若只需要 RGB，其他 ROS 节点仍可只订阅 RGB 话题；但在这台 D405/WSL2 组合上不要关闭相机的深度流，否则已观察到 RGB 画质异常。该结论来自当前设备和透传环境的实测。

## 4. 断开设备

在普通 PowerShell 中把设备还给 Windows：

```powershell
usbipd detach --busid <BUSID>
```

## 5. 故障排查

- `usbipd list` 在 Windows 中也看不到相机：检查 Windows 设备管理器、USB 3 接口和数据线。
- Windows 能看到、Ubuntu 的 `lsusb` 看不到：确认 WSL 为版本 2（`wsl --list --verbose`），保持 WSL 终端打开后重新执行 `usbipd attach --wsl --busid <BUSID>`；也可在 Windows 运行 `wsl --update` 更新 WSL 内核。
- `lsusb` 能看到、`rs-enumerate-devices` 看不到：检查 RealSense SDK/udev 规则和 USB 连接，尝试将相机直连电脑而非经由扩展坞。
- SDK 能识别但 ROS 2 未发现设备：确认 `realsense2_camera` 使用的 librealsense 与系统安装版本匹配，并检查启动日志中的设备枚举错误。
- 日志出现 `Device USB type: 2.1` 或 `Reduced performance is expected`：这次相机连接被识别为 USB 2.x，性能会受限。检查相机是否直连电脑 USB 3 接口，换用确认支持 SuperSpeed 的数据线，并避免扩展坞、前置面板或无源 Hub。拔插后在 Windows 重新执行 `usbipd attach`，再检查启动日志中的 USB 类型是否改善。USB 类型应以当前 ROS 启动日志为准；Windows Viewer 的连接信息不能代表相机附加到 WSL 后的实际链路状态。
- 相机已启动但持续出现 `USB SCP overflow`、`Frames didn't arrive within 5 seconds` 或 `Frames Timeout`：ROS 节点虽已启动，图像流仍不可靠。先看本次日志中的 USB 类型；若已是 `3.2`，无需再按 USB 2.x 问题排查，重点检查透传和视频流。先完全退出 Windows RealSense Viewer，确认没有其他程序占用相机，然后重新附加设备并启动 ROS；可尝试关闭非必需视频流或降低分辨率/帧率，具体 profile 以相机支持的模式为准。若日志还出现 `Left MIPI error`，这是相机传感器数据链路错误，也应记录出现频率并测试单独运行相机。若在 WSL2 透传下仍反复报错，可在原生 Ubuntu 环境用相同 profile 验证，以区分 WSL USB/IP 传输问题和相机本身问题。
- `ros2 topic list` 只看到 `/parameter_events`、`/rosout`，或看不到相机节点：检查 ROS 2 CLI daemon。先在已加载 ROS 环境的终端启动 `ros2 daemon start`，再启动相机；另一终端运行 `ros2 node list` 和 `ros2 topic list`。若 daemon 状态异常，可运行 `ros2 daemon stop` 后再 `ros2 daemon start`。本机 D405 测试中，显式启动 daemon 后节点 `/camera/camera` 和深度话题 `/camera/camera/depth/image_rect_raw` 可见，实测约 5.1 Hz。
