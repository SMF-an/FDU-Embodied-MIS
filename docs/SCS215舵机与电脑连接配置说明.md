# SCS215 舵机与电脑连接配置

本文说明双臂 Web 遥控器使用 Feetech SCS215 舵机时的 USB 串口配置。当前方案由 Web 遥控器进程直接访问串口，不启动舵机 ROS 2 节点，也不提供舵机 ROS topic 或 service。

## 1. 接线与设备识别

左右舵机分别连接电脑的 USB 串口转换器。建议使用 `/dev/serial/by-id/` 下的稳定设备链接，不要把 `ttyACM0` 或 `ttyACM1` 当作永久编号；USB/IP 重连后编号可能变化。

```bash
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null
ls -l /dev/serial/by-id/
lsusb
dmesg --follow
```

当前配置中的左侧串口使用稳定路径：

| 机械臂 | 配置串口 |
| --- | --- |
| 左臂 | `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B90152150-if00` |
| 右臂 | 根据第二个转换器的 `by-id` 链接填写 |

插拔某一路设备时，观察对应的 `by-id` 链接和实际串口；左右关系应通过一次只连接一路的方式确认。

## 2. WSL2 USB 透传

如果项目运行在 WSL2，在管理员 PowerShell 中确认设备：

```powershell
usbipd list
```

将对应的 `<BUSID>` 绑定并附加到 WSL：

```powershell
usbipd bind --busid <BUSID>
usbipd attach --wsl --busid <BUSID>
```

回到 Ubuntu 后再次检查 `/dev/ttyACM*` 或 `/dev/ttyUSB*`。WSL、Windows 重启或设备重新插拔后，通常需要重新执行 `usbipd attach`。

## 3. 串口权限

```bash
id
ls -l /dev/ttyACM0 /dev/ttyACM1
```

如果设备属于 `dialout` 组，将当前用户加入该组后重新登录 WSL：

```bash
sudo usermod -aG dialout "$USER"
```

Web 遥控器不建议用 `sudo` 启动；长期运行应让普通用户拥有串口访问权限。

## 4. 安装并验证 SDK

使用 ROS 运行时的 Python 解释器安装 SDK，避免 Conda Python 与 ROS Python 不一致：

```bash
/usr/bin/python3 -m pip install --user ftservo-python-sdk
/usr/bin/python3 -c "import scservo_sdk; print(scservo_sdk.__file__)"
```

## 5. 配置左右舵机

编辑 `src/ros2_rm_robot/rm_rcm_web_teleop/config/scs215.yaml`，确认串口、ID、波特率和开合位置：

```yaml
servos:
  left:
    port: "/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B90152150-if00"
    servo_id: 1
    baud_rate: 1000000
    open_position: 762
    close_position: 806
    speed: 50
  right:
    port: "/dev/serial/by-id/<右侧转换器的稳定链接>"
    servo_id: 1
    baud_rate: 1000000
    open_position: 380
    close_position: 260
    speed: 50
```

- `port` 是实际 USB 串口。
- `servo_id` 和 `baud_rate` 必须与舵机当前设置一致。
- `open_position`、`close_position` 需要根据机构方向和限位标定。
- `speed` 是位置命令速度，程序限制在 `1` 到 `100`。

该控制是位置控制，不是力控。修改位置时先使用较小的位置差，避免夹伤、撞限位或拉扯线缆。

## 6. 启动与验证

在工作区根目录执行：

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch rm_rcm_web_teleop dual_web_teleop.launch.py
```

启动日志会分别报告左右舵机的串口、ID 和连接结果。浏览器打开 `http://127.0.0.1:8765`，页面中的“打开”和“闭合”按钮会直接发送位置命令。

启动前确认舵机周围安全、急停可用、串口未被其他程序占用，并且配置中的端口映射正确。关闭 Web 遥控器时，程序会尝试关闭两路舵机力矩并释放串口；异常断电时仍应使用机械急停或断电措施。

## 7. 故障排查

### 找不到 SDK

```bash
/usr/bin/python3 -c "import scservo_sdk"
```

失败时使用 `/usr/bin/python3` 安装 SDK，并重新构建 Web 包。

### 无法打开串口

```bash
fuser -v /dev/ttyACM0
fuser -v /dev/ttyACM1
```

检查设备是否存在、用户是否属于 `dialout`，并关闭旧的 Web 遥控器、串口调试工具或其他舵机程序。

### ping 失败或通信结果异常

依次核对 USB 透传、串口编号、波特率、舵机 ID、供电和信号线。电脑识别到 USB 串口不代表舵机总线已经正常通信；建议先只连接一路做测试。

### 页面显示舵机串口未连接

页面状态来自 Web 后端启动时的串口连接结果。修改 YAML 或重新插拔设备后，必须完全退出并重新启动 Web 遥控器；刷新浏览器不会重新初始化串口。

### 左右舵机方向相反

分别调整 `open_position` 和 `close_position`，先小范围测试，再逐渐扩大位置差。这是机构安装方向和目标位置的问题，不是 ROS topic 方向问题。
